ويز اليوسفية — تحديث المرحلة الثالثة والرابعة

المرحلة الثالثة — نبض اليوسفية:
- اختيار نوع المنشور من لوحة الإدارة (خبر / تنبيه / عرض).
- لون البطاقة يتغير تلقائياً حسب النوع: الخبر أبيض، التنبيه أحمر، والعرض أخضر.
- فلاتر للتصنيفات، تحديث يدوي، وحالة واضحة عند عدم وجود منشورات.
- إظهار تنبيه قرب انتهاء المنشور.

المرحلة الرابعة — طلبات الخدمات:
- المستخدم المسجل يرسل طلب خدمة مع النوع والمنطقة ورقم التواصل والتفاصيل.
- يستطيع المستخدم متابعة حالة طلباته السابقة.
- الإدارة تستطيع تحديث حالة الطلب.
- أضيف زر تواصل واتساب داخل كل طلب إداري، مع رسالة جاهزة مرتبطة بنوع الطلب والمنطقة.
- بعد نجاح إرسال الطلب يتم تفريغ الحقول لمنع إعادة إرسال البيانات القديمة بالخطأ.

قاعدة البيانات:
- ملف stage3-4-migration.sql يتضمن جدولي community_posts وservice_requests وسياسات RLS.
- إذا لم تنفذ الملف سابقاً، نفذه مرة واحدة في Supabase SQL Editor. إذا نفذته بنجاح فلا تعِد تشغيله دون داعٍ.
- تأكد أن حساب الإدارة يحمل profiles.role = 'admin'.

التحقق:
- تم فحص صياغة JavaScript باستخدام node --check وتحليل HTML الأساسي.
- لم يتم الاتصال بمشروع Supabase الحي أو اختبار إرسال الطلبات وفتح واتساب على جهاز فعلي؛ يلزم اختبارها بعد رفع النسخة وربطها بقاعدة بياناتك.
