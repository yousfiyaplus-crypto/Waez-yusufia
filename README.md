# ويز اليوسفية

منصة محلية (PWA) لمنطقة اليوسفية – بغداد: دليل محلات وخدمات، خريطة تفاعلية، «نبض اليوسفية» (أخبار/تنبيهات/عروض)، طلبات خدمات، إشعارات لحظية، لوحة صاحب المشروع، ولوحة إدارة.
التقنية: HTML/CSS/JavaScript عادي (بدون Build) + Supabase (قاعدة بيانات، مصادقة، Realtime، تخزين) + Leaflet.

## هيكل المشروع
| المسار | الوصف |
|---|---|
| `index.html` | الواجهة والأنماط وسياسة CSP |
| `js/actions.js` | ربط كل الأحداث (`data-action`) بقائمة بيضاء، بلا inline handlers |
| `js/*.js` | وحدات التطبيق (config, auth, shops, map, owner, admin, notifications...) |
| `sw.js` | Service Worker: كاش وعمل دون اتصال |
| `stage3-4-migration.sql` | جداول: النبض، الطلبات، الإشعارات |
| `stage5-security-hardening.sql` | **تحصين الأمان داخل قاعدة البيانات (إلزامي قبل الإطلاق)** |
| `_headers` | ترويسات أمان (Netlify / Cloudflare Pages) |
| `tools/set-domain.sh` | ضبط النطاق الحقيقي في canonical/robots/sitemap |
| `tests/e2e-smoke.py` | اختبار تشغيل بالمتصفح (Playwright) مع محاكاة Supabase |

## خطوات الإطلاق
1. **قاعدة البيانات** (Supabase → SQL Editor، بهذا الترتيب، بعد نسخة احتياطية):
   `stage3-4-migration.sql` ثم `stage5-security-hardening.sql`.
   ثم نفّذ استعلام `pg_policies` الموجود آخر ملف التحصين وتأكد أنه لا توجد سياسة قديمة تسمح للجميع بالكتابة (السياسات تُجمع بـ OR).
2. **النطاق**: `./tools/set-domain.sh https://نطاقك.com`
3. **الرفع**: ارفع المجلد كما هو على أي استضافة ثابتة (Netlify / Cloudflare Pages / Vercel / GitHub Pages). على Netlify/Cloudflare يعمل `_headers` تلقائياً؛ على غيرها انقل الترويسات لإعدادات الاستضافة.
4. في Supabase → Authentication → URL Configuration: أضف نطاقك في Site URL وRedirect URLs (لاستعادة كلمة المرور).
5. اختبر على النسخة المنشورة: تصفح، تسجيل، طلب خدمة، إضافة مشروع، دخول الإدارة.

## ما تغيّر في هذه النسخة
**الأمان**
- ملف `stage5-security-hardening.sql`: منع صاحب المشروع من اعتماد مشروعه/ترقيته/تزوير عدّاداته، منع اعتماد التقييم ذاتياً وانتحال الاسم، منع تصعيد الصلاحيات إلى admin، حدّ 5 طلبات خدمة بالساعة، حماية الإشعارات، وقيود رفع الصور (2MB، jpeg/png/webp، مجلد المستخدم فقط).
- حذف كل الـ `onclick`/`oninput`/`onerror` (أكثر من 90) واستبدالها بتفويض أحداث آمن، وتفعيل **Content-Security-Policy** صارمة (لا `unsafe-inline` للسكربتات).
- تهريب الروابط والصور (`https` فقط) وتهريب رسائل الأخطاء في التنبيهات (Toast).
**الاعتمادية**
- إصلاح احتمال تعليق Supabase بسبب `await` داخل `onAuthStateChange`.
- معالجة أخطاء العمليات الإدارية وصاحب المشروع (كانت تُتجاهل بصمت) وتأكيد قبل حذف التقييم، وشاشة خطأ مع «إعادة المحاولة» عند فشل التحميل.
- حماية قراءة المفضلة من بيانات تالفة في `localStorage`.
**الواجهة والميزات**
- Skeleton loaders للقائمة والنافذة والإشعارات والطلبات والإدارة.
- ترتيب النتائج (الأنسب / الأقرب / الأعلى تقييماً / المفتوح أولاً / الأحدث).
- زر مشاركة المشروع (Web Share أو نسخ الرابط).
- إحصائيات صاحب المشروع: زيارات، تواصل، نسبة التواصل، متوسط التقييم.
- تنبيهات المتصفح عند وصول إشعار جديد والتطبيق مفتوح.
- إمكانية وصول: إعادة السماح بالتكبير بالإصبعين، رابط «تخطّي للمحتوى»، احترام `prefers-reduced-motion`.
- PWA: Service Worker v8 (كاش للمكتبات الخارجية المثبّتة، stale-while-revalidate، عمل دون اتصال)، `robots.txt` و`sitemap.xml`.

## حدود معروفة (غير منفّذة عمداً)
- **Push في الخلفية** (والتطبيق مغلق): يحتاج خادماً/Edge Function ومفاتيح VAPID.
- **الحجز والدفع الإلكتروني**: يحتاج قرارات تجارية وحساب بوابة دفع (مثل ZainCash/FIB).
- **SRI** على سكربتات CDN: لم تُضف لعدم إمكانية حساب البصمات دون شبكة؛ يمكن إضافتها أو استضافة المكتبات محلياً.
- `style-src` يبقى فيه `'unsafe-inline'` لأن الواجهة تستخدم `style=""` كثيراً.
- ما اختُبر على Supabase الحقيقي: الاختبار الآلي يحاكي Supabase. شغّل SQL ثم اختبر السيناريوهات يدوياً.

## تطبيق أندرويد/iOS (اختياري)
الأسهل: يُثبَّت كـ PWA من المتصفح. لحزمة APK: استخدم [Capacitor](https://capacitorjs.com) (`npm i @capacitor/core @capacitor/cli`، `npx cap init`، اجعل `webDir` هو هذا المجلد، ثم `npx cap add android`).
