ويز اليوسفية — النسخة التأسيسية لتجربة المنصة اليومية

الهدف العام:
تحويل ويز اليوسفية من دليل أماكن فقط إلى منصة محلية يومية تجمع المجتمع المحلي والدليل والخدمات وطلبات المستخدمين، مع إبقاء التصفح العام مفتوحاً للجميع واشتراط الحساب للطلبات والتفاعل والإجراءات الشخصية.

ما أُنجز في هذه النسخة (المرحلة التأسيسية — تجربة الدخول اليومية):
- إضافة «بوابة ويز اليومية» إلى الصفحة الرئيسية كمدخل واضح للأقسام الأساسية.
- اختصارات مباشرة إلى نبض اليوسفية، اكتشاف الأماكن، طلب خدمة، ومساحة المشروع.
- رسالة ترحيب تتغير حسب الوقت، وتعرض الاسم الأول عند تسجيل الدخول.
- توضيح أن التصفح متاح للجميع، بينما الحساب مطلوب للطلبات والتفاعل.
- تحديث وصف هوية المنصة في الترويسة من دليل وخريطة فقط إلى مجتمع وخدمات وحياة يومية.
- تحديث نسخة Service Worker حتى تصل تغييرات الواجهة للمستخدمين بعد النشر.

الموجود مسبقاً ويستمر بالعمل:
- الدليل والبحث والخريطة والتصفية.
- نبض اليوسفية مع تصنيف المنشورات وألوان الخبر/التنبيه/العرض.
- طلبات الخدمات ومتابعتها وتوجيهها من الإدارة حسب نسخة المرحلة الرابعة.
- إدارة المشاريع والتقييمات ولوحة الإدارة.

مهم:
- هذه بداية إعادة تنظيم تجربة المنصة وليست ادعاءً بأن جميع الأنظمة المستقبلية اكتملت.
- لم يتم اختبار اتصال Supabase الحي أو إجراء نشر فعلي في هذه الخطوة.
- لم تتغير قاعدة البيانات في هذه المرحلة، لذلك لا تحتاج Migration جديدة بسبب بوابة ويز اليومية.
- لا تستبدل إعدادات Supabase أو مفاتيح المشروع الموجودة في app.js.

التحقق المنفذ:
- node --check على app.js.
- تحليل HTML الأساسي بنجاح.
- يلزم اختبار التصفح وتسجيل الدخول والطلبات على النسخة المنشورة قبل اعتمادها نهائياً.


المرحلة التالية — مركز النشاط والإشعارات:
- إضافة تبويب مستقل لمركز النشاط مع قائمة إشعارات شخصية.
- شارة بعدد الإشعارات غير المقروءة في شريط التنقل.
- إمكانية تمييز إشعار كمقروء أو قراءة كل الإشعارات الشخصية.
- تحديث لحظي عبر Supabase Realtime عند وصول إشعار جديد.
- إنشاء إشعار تلقائي لصاحب الطلب عند تغيّر حالة طلب الخدمة أو تعيين مقدم خدمة.
- إضافة جدول user_notifications وسياسات RLS وفهرسة وفنكشن/Trigger داخل ملف SQL المرفق.

مهم: شغّل ملف stage3-4-migration.sql كاملاً مرة واحدة في Supabase بعد أخذ نسخة احتياطية/مراجعة الجداول الحالية. إذا كان قد شُغّل سابقاً، أعد تشغيله لتطبيق الجزء الجديد؛ أو نفّذ فقط القسم الأخير الخاص بمركز النشاط. لم يتم اختبار الاتصال الحي أو سياسات RLS على مشروع Supabase الفعلي.

ملاحظة: مركز النشاط والإشعارات الموصوف أعلاه كـ"المرحلة التالية" منفّذ فعلياً الآن ضمن الكود (`js/notifications.js`) — هذا القسم من التوثيق كان متأخراً عن الكود الفعلي قبل تحديث إعادة الهيكلة أدناه.

## تحديث: إعادة هيكلة واحترافية (Refactor + SEO + UX)

ما تم تنفيذه فعلياً في هذا التحديث:

- **تقسيم app.js إلى وحدات**: الملف الواحد (١٤٣٣ سطر) مقسّم الآن إلى 13 ملف منطقي تحت `js/` (`config`, `utils`, `auth`, `router`, `requests`, `community`, `filters`, `map`, `shops`, `shop-modal`, `owner`, `admin`, `notifications`, `main`). كلها Scripts عادية (غير `type="module"`) محمّلة بترتيب محدد كي تبقى كل الدوال في النطاق العام (`window`) تماماً كالسابق، فلا تنكسر أي أزرار `onclick`. تم التحقق من تطابق المحتوى حرفياً مع النسخة الأصلية (`node --check` لكل ملف + مقارنة شاملة) قبل حذف `app.js` القديم.
- **روابط عميقة للمشاريع (`#shop-<id>`)**: فتح مشروع الآن يحدّث الرابط تلقائياً (`js/router.js`)، فتقدر تشارك رابط مشروع معيّن مباشرة أو يفهرسه Google كصفحة مستقلة.
- **بيانات LocalBusiness (JSON-LD)**: تُحقن تلقائياً عند فتح أي مشروع لتحسين ظهوره في نتائج البحث المحلي.
- **استعادة كلمة المرور**: زر "نسيت كلمة المرور؟" في شاشة الحساب + مسار كامل عبر `supabase.auth.resetPasswordForEmail` و`updateUser`.
- **إصلاحات Accessibility/SEO أساسية**: حذف `user-scalable=no` من الـviewport، إضافة `meta description` و`Open Graph` و`JSON-LD` للصفحة الرئيسية.
- **تثبيت إصدار supabase-js** على `2.119.0` بدل `@2` المفتوح (لمنع انكسار مفاجئ عند صدور تحديث).
- **Service Worker**: تحديث قائمة الملفات المخزّنة (`CACHE_NAME = v5`) لتشمل ملفات `js/` الجديدة.

### لم يُنفَّذ (ونوصي به صراحة كخطوة تالية)
- **استبدال onclick="" الكامل بـ event delegation**: البنية الحالية فيها أكثر من ٧٠ موضع `onclick` داخل HTML مولّد ديناميكياً (بطاقات المشاريع، لوحة الإدارة، الطلبات...). تحويلها بالكامل تحسين حقيقي (يسمح لاحقاً بتفعيل Content-Security-Policy صارمة)، لكنه تعديل واسع وعالي الخطورة على كود لا يمكن تشغيله فعلياً هنا لاختباره حيّاً مقابل Supabase — تم تأجيله عمداً بدل تسليمه بدون اختبار.
- رابط `canonical` في `index.html` حالياً نص توضيحي (`https://waez-yusufiya.example/`) — **بدّله بدومينك الفعلي بعد النشر**.
- لم يتم تنفيذ اختبار حيّ (تسجيل دخول، إرسال طلب، إلخ) مقابل مشروع Supabase الفعلي — كل التحقق هنا كان على مستوى الصياغة البرمجية (`node --check`) ومطابقة المنطق، وليس تشغيلاً فعلياً في متصفح.
- Skeleton loaders/حالات تحميل أدق لكل شاشة لم تُضف بعد (أغلب الشاشات عندها رسالة "جاري التحميل..." نصية بسيطة فقط).

## تحديث v3: أيقونات SVG + خريطة تفاعلية

- `js/icons.js` (جديد): مكتبة أيقونات SVG موحّدة. أيقونة كل قسم تُحدَّد تلقائياً من اسم القسم (أو الإيموجي القديم) دون تعديل قاعدة البيانات.
- `js/map.js` أُعيدت كتابته: طبقة خريطة داكنة (CARTO) مع زر تبديل للفاتحة، دبابيس SVG حسب القسم (نقطة خضراء/حمراء للحالة، والمميز ذهبي نابض)، تجميع الدبابيس، بطاقة معاينة عند اللمس، أدوات عائمة (موقعي / عرض الكل / النمط / تكبير)، ومسار ذهبي.
- إصلاح: تغيير المفضلة كان يحسب «زيارة» جديدة للمشروع في كل ضغطة.
- `icon.svg` أيقونة موقع/تطبيق، وSW ← v6.
- ملاحظة: طبقات CARTO مجانية للاستخدام الخفيف؛ للاستخدام التجاري الكبير راجع شروطهم أو بدّل الرابط في `TILE_URLS`.
- لم يُختبر في متصفح حيّ ولا مع Supabase الفعلي.
