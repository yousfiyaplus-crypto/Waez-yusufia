ويز اليوسفية — تحديث المرحلة الثالثة والرابعة

المرحلة الثالثة — نبض اليوسفية:
- اختيار نوع المنشور من لوحة الإدارة (خبر / تنبيه / عرض).
- لون البطاقة يتغير تلقائياً حسب النوع: الخبر أبيض، التنبيه أحمر، والعرض أخضر.
- فلاتر للتصنيفات، تحديث يدوي، وحالة واضحة عند عدم وجود منشورات.
- إظهار تنبيه قرب انتهاء المنشور.

المرحلة الرابعة — وسيط طلبات الخدمات:
- المستخدم المسجل يرسل طلباً مع نوع الخدمة والمنطقة ورقم التواصل والتفاصيل.
- المستخدم يتابع حالة الطلب من حسابه.
- الإدارة تراجع الطلب وتتواصل مع صاحب الطلب عبر واتساب.
- الإدارة تسجل اسم مقدم الخدمة ورقم هاتفه وملاحظة اختيارية، ثم تحفظ التوجيه.
- بعد حفظ التوجيه تظهر بيانات مقدم الخدمة للمستخدم، مع رابط واتساب إذا كان الرقم عراقياً صالحاً.
- تبقى الإدارة قادرة على تحديث حالة الطلب إلى قيد المتابعة أو مكتمل أو ملغي.
- بعد نجاح إرسال الطلب يتم تفريغ الحقول لمنع إعادة إرسال البيانات القديمة بالخطأ.

طريقة العمل المقصودة:
1) يصل الطلب إلى لوحة الإدارة.
2) تتواصل الإدارة مع صاحب الطلب لفهم الاحتياج عند الحاجة.
3) تختار الإدارة مقدم خدمة مناسباً وتتواصل معه.
4) تسجل اسمه ورقمه وملاحظتها، ثم تضغط «حفظ التوجيه وإبلاغ المستخدم».
5) تظهر بيانات مقدم الخدمة في «طلباتي السابقة» لدى صاحب الطلب.

قاعدة البيانات:
- ملف stage3-4-migration.sql يتضمن جدولي community_posts وservice_requests وسياسات RLS.
- أضيفت أعمدة ربط مقدم الخدمة بطريقة آمنة باستخدام ADD COLUMN IF NOT EXISTS؛ شغّل ملف SQL بعد رفع هذه النسخة حتى لو كان الجدول موجوداً من قبل.
- تأكد أن حساب الإدارة يحمل profiles.role = 'admin'.

التحقق:
- تم فحص صياغة JavaScript باستخدام node --check وتحليل HTML الأساسي.
- لم يتم الاتصال بمشروع Supabase الحي أو اختبار إرسال الطلبات وفتح واتساب على جهاز فعلي؛ يلزم اختبارها بعد رفع النسخة وربطها بقاعدة بياناتك.
